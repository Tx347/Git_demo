Git 学习笔记

改 → add → commit，中间用 status 随时确认

一、三个抽屉（理解一切的基础）

你的改动在 Git 里会经历三个位置，所有命令本质都是在它们之间搬东西：

工作区
你正在改的文件
还没告诉 Git
→
暂存区
add 之后
已选中待提交
→
仓库
commit 之后
永久存档

① git add：工作区 → 暂存区　② git commit：暂存区 → 仓库　③ git restore：往回搬（撤销改动）

二、核心命令（背下这 8 个就够日常用）

命令干什么什么时候用
git init把文件夹变成 Git 仓库全新项目第一次用
git status看当前状态最常用，没把握就先敲它
git add .把所有改动加入暂存区提交前
git commit -m "说明"正式提交每完成一个小成果
git log --oneline看提交历史回顾进度
git diff看具体改了哪几行提交前确认
git restore 文件名撤销改动，回到上次提交改坏了要还原
git checkout -b 分支名开新分支想试验新想法

三、一日工作流

1
写代码 / 练习
写第 N 课练习，保存
2
看状态
git status
3
选中所有改动
git add .
4
提交并写清说明
git commit -m "今天做了啥"
5
回顾进度（可选）
git log --oneline

四、进阶命令（需要时再学）

场景命令
推到 GitHub 云端备份git push
拉取别人的更新git pull
下载别人的项目git clone 网址
切换分支git checkout 分支名
合并分支git merge

五、两条黄金法则

  • 小步提交 —— 别攒一大堆改动才提交一次，每完成一个能说清楚的小成果就提交。
  • 提交信息写清楚 —— 别写"改了一下"，要写"加了温度报警函数"。三个月后你会感谢现在的自己。
一句话记住：Git 用得好不好，不在命令记多少，而在提交习惯。你已经会用了，缺的只是熟练。
